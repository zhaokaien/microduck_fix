# 文档维护、导航与 SEO 规则

[返回资料索引](README.md)

## 三层信息架构

```text
L1  README.md
L2  docs/<任务分类>/README.md
L3  docs/<任务分类>/<具体问题>.md
```

禁止继续创建四级目录。一个问题的操作、验证、原理和常见错误放在同一篇 L3 文档里，用二级或三级标题分区即可。

同一层级之间的交叉链接不算加深层级；但任何关键资料都必须能从首页、分类页或完整索引直接到达。

## 从三个上游项目提炼出的结构

- 来自官方 MicroDuck：先说明“这是什么”，再按“手里已有鸭子 / 正在开发”分流。
- 来自 fanhao 复刻项目：按机械、电气、软件、训练分模块，并展示真实实机进度。
- 来自 kissqy 复刻项目：首屏给出预算、装配、刷机和进阶四条可选路线，让新手跳过无关步骤。

本项目的取舍是：只保留一个主路线，把“找痛点”放在首页，把完整资源收进分类页，把视频、团购和社群作为可信度与行动入口，而不是铺满首屏。

## 页面命名

- 文件名使用小写英文和连字符，例如 `servo-calibration.md`，方便长期引用和搜索。
- 一个文件名只表达一个主题，不使用 `misc`、`other`、`notes2`。
- 标题必须直接表达新手会搜索的问题，例如“飞特舵机 ID 冲突怎么办”，不要只写“问题记录”。
- 页面移动时保留旧路径或增加跳转说明，避免外部搜索结果失效。

## 内容规则

- 先写可执行的结论，再写推导过程。
- 硬件问题必须写型号、版本和接线位置。
- 实测数据必须说明测试条件；单次现象不能写成普遍结论。
- 不把旧教程直接删掉，可以归档并标注失效原因。
- 图中要有描述性 `alt` 文本，避免“图片1”“截图”这种无意义名称。
- 不堆砌关键词。标题、首段和正文自然覆盖用户真正会搜索的词。

## GitHub 与搜索引擎优化

首页优先覆盖这些真实搜索意图：

- MicroDuck 复刻
- Radxa Zero 3W MicroDuck
- 飞特 HD-1910 MicroDuck
- MicroDuck HAT / IMU_TO_DXL
- 舵机标定、总线丢帧、强化学习训练

维护时同时检查：

1. README 首屏是否在一段话内说明项目、适用人群和当前进度。
2. 首页是否存在稳定、描述清晰的站内链接。
3. 分类页是否链接到所有 L3 文档。
4. 图片文件名和 `alt` 是否包含主题信息。
5. 仓库名称、GitHub Description 和 Topics 是否包含核心关键词。
6. 旧链接是否仍能访问。
