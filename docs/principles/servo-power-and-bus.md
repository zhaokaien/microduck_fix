# 供电、舵机总线与丢帧

[返回原理索引](README.md) · [返回首页](../../README.md)

## 系统链路

```text
2S 电池
  → HAT 电源输入
  → DC-DC 5V
  → Radxa 主控

2S 电池
  → 舵机电源
  → 15 路舵机

Radxa UART
  → HAT 电平/方向电路
  → 舵机共享总线
```

不同 HAT 的具体拓扑可能不同，但核心问题相同：**控制信号必须可靠，舵机电流必须走独立的低阻路径，所有设备必须有共同参考地。**

## 为什么舵机一动，主控会重启

舵机启动和堵转时会产生很大的瞬态电流。若电池、线材、连接器或 HAT 的输出阻抗过高，电压会瞬间下降：

- 主控触发欠压复位。
- SD 卡写入失败或系统重启。
- 舵机自身重启并重新初始化。
- USB、网络和摄像头同时掉线。

平均电流看起来正常，不代表瞬态电流足够。电源和线材必须按峰值负载设计。

## 为什么丢帧不一定是波特率问题

智能舵机通常共享一条半双工总线。主控发送命令后等待舵机应答，应答需要满足：

- 电平正确。
- 方向切换及时。
- 地线参考稳定。
- 总线没有被错误 ID 或故障设备长期占用。
- 控制循环没有在上一次事务未结束时再次发送。

电源波动、地弹、长线和分支反射都可能让一个本来正确的协议帧被读错。

## 分层排查

| 层级 | 要证明什么 |
|---|---|
| 电池 | 满电和低电量都能提供峰值电流 |
| 线材与连接器 | 满载压降和接触电阻可接受 |
| HAT 电源 | 5V 在舵机动作时不跌落 |
| HAT 信号 | 电平、方向和空闲状态正确 |
| 总线 | ID 唯一、协议一致、无阻塞 |
| 固件 | 超时、重试和错误处理不会拖垮控制循环 |

## 工程原则

- 电源线和信号线分开规划。
- 舵机电源不要从脆弱的小电流接口取电。
- 地线要能承受回流，不只是“能通电”。
- 先保证单设备和少设备稳定，再扩展到 15 个。
- 不能用软件重试掩盖电气问题。

## 如何验证

- 同时测量电池输入、5V 和舵机端电压。
- 记录异常发生前后的控制周期和错误计数。
- 对比不同舵机数量下的故障阈值。
- 对比短线/长线、单点/多点接地和不同连接器。
- 固定动作重复测试，确认修复不是偶发。
