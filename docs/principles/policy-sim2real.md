# 控制回路、ONNX 策略与 sim2real

[返回原理索引](README.md) · [返回首页](../../README.md)

## 一次控制循环发生什么

```text
读取 IMU 与关节反馈
  → 组成 observation
  → 归一化、重排、检查时间戳
  → ONNX 策略推理
  → 得到 15 个关节目标
  → 限幅、插值、安全检查
  → 写入舵机总线
  → 等待下一个控制周期
```

MicroDuck 参考实现以约 50Hz 运行控制循环。任何环节变慢、阻塞或数据错位，都可能让动作变差。

## 策略输入为什么敏感

神经策略学习的是“在某个状态下输出某个动作”的映射。它依赖：

- 关节顺序。
- 角度单位和正负方向。
- IMU 坐标系。
- 历史帧长度。
- 控制频率。
- 归一化参数。

只要其中一项与训练时不同，模型就可能输出完全错误的动作。

## ONNX 是什么

ONNX 是训练框架导出模型后的通用推理格式。机载程序可以加载 ONNX，在 CPU 或 NPU 上执行，而不需要安装完整训练环境。

但 ONNX 只保存网络计算图，不自动包含：

- 正确的观测构造。
- 关节标定。
- 舵机参数。
- 安全限幅。
- 仿真与真机差异。

因此“模型文件能加载”不等于“机器鸭能走”。

## sim2real 的误差来源

| 来源 | 仿真 | 真机 |
|---|---|---|
| 质量与惯量 | 理想参数 | 打印误差、螺丝、线材和电池改变重心 |
| 舵机 | 理想力矩/速度 | 齿隙、延迟、温升和堵转 |
| 接触 | 简化摩擦 | 桌面、地毯和脚底磨损不同 |
| IMU | 无噪声或理想噪声 | 振动、零偏和安装误差 |
| 控制 | 固定时间步 | 调度抖动、过热降频 |
| 电源 | 理想电压 | 电池压降和瞬态干扰 |

## 真机验证顺序

1. 检查模型输入和输出的维度、顺序、单位。
2. 对比仿真与真机的关节零位和方向。
3. 关闭策略，手动测试每个关节。
4. 只用 HOME 和固定姿态验证反馈。
5. 限制速度、力矩和动作范围。
6. 短时运行，记录关节、IMU、电压和控制周期。
7. 每次只改一个 sim2real 参数。

## 为什么“仿真成功”不够

仿真中的策略可能利用了不真实的接触、执行器速度或状态信息。没有经过真机验证的策略，只能说明训练闭环成立，不能说明机器人可以安全运行。

## 最低可信结论

至少需要在同一硬件上重复完成目标动作，并保留日志、参数和失败样本。单次成功视频不能替代可复现验证。
