# 主控与舵机过热、降频

[返回排障索引](README.md) · [返回首页](../../README.md)

**一句话结论：** 过热会让主控降频、服务响应变慢并放大丢帧；先把未使用的服务和堵转排除，再做风道与散热。

**状态：** 待补充本机实测

## 现象

- 主控越来越慢，网页或遥控响应延迟。
- CPU 频率长期停在最低档。
- 舵机外壳明显发热、保持时啸叫。
- IMU 或总线偶发超时，降温后恢复。
- 摄像头、音频等未安装服务反复重启。

## 最短排查步骤

1. 记录空闲和负载下的 CPU 温度、频率。
2. 停止未使用的摄像头、ToF、音频或调试服务。
3. 卸掉机械负载，确认舵机是否仍然快速升温。
4. 检查关节是否顶死、零位错误或持续输出大扭矩。
5. 记录电池电压和舵机电流，排除供电和堵转。
6. 最后再改外壳开孔、散热片和风道。

## 散热检查

- 进风口和出风口是否形成真实气流路径。
- 主板芯片、HAT 和电池是否被封闭在无风区域。
- 风扇是否只吹外壳，没有经过发热表面。
- 风扇供电是否与传感器共用脆弱电源。
- 入风口是否被线束、外壳或桌面挡住。

## 如何验证

- 使用相同动作、相同持续时间比较修改前后。
- 同时记录温度、频率、控制周期和丢帧计数。
- 降温后重新测试，确认问题是否随温度变化。
- 不只看“摸起来不热”，要有温度与频率数据。

## 经验参考

fanhao 的实机记录中，未安装摄像头和 ToF 时相关服务会反复重启，主控温度升高并触发降频；关闭未使用服务后仍需进一步改善整机风道。具体数值应以本机复测为准。

## 完成标准

- 连续运行目标时长后，温度不再持续上升。
- CPU 不长期停留在最低频率。
- 控制周期和网络响应稳定。
- 舵机保持和运动时没有异常温升与啸叫。
