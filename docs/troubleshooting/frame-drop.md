# 丢帧、重启与总线不稳定

[返回排障索引](README.md) · [返回首页](../../README.md)

**一句话结论：** “丢帧”通常不是单一软件 bug，而是供电瞬态、地线回流、总线负载、线材和固件时序共同造成的结果。

**状态：** 进行中

## 先分清三种现象

| 现象 | 常见方向 |
|---|---|
| 控制循环偶尔漏读某个舵机 | 总线时序、线材、ID、固件 |
| 多舵机动作时整组掉线 | 电源瞬态、连接器、地线 |
| 主控重启或舵机重启 | 电压跌落、堵转电流、电池或 5V 供电 |

不要把“整机重启”当成“串口丢帧”，两者的排查顺序不同。

## 最短排查步骤

1. 只接主控和 HAT，运行 10 分钟，确认主控不重启。
2. 接一个舵机，反复正反转，观察电压、温度和通讯。
3. 接 3–5 个舵机，做同时加速。
4. 分批加到 15 个，记录开始出现问题的数量。
5. 出现问题后，不改软件，单独加强供电或缩短地线，观察是否变化。
6. 只在供电稳定后，再检查波特率、超时、重试和协议实现。

## 重点检查

- 电池是否老化，满电和低电量时是否表现不同。
- HAT 输入、5V 输出和舵机端电压是否在动作瞬间跌落。
- 主控、HAT、舵机和电池是否形成可靠的低阻抗回流路径。
- 舵机总线是否使用短线、可靠端子和合理分支。
- 15 个舵机的 ID 是否唯一，是否有设备重复应答。
- IMU 是否固定为 ID 200，是否与舵机 ID 或协议发生冲突。
- 左右腿总线上行到颈部后的手工汇合点是否可靠，电源和信号线是否接错。
- 固件是否会因为单个超时阻塞整个控制循环。
- 音频、IMU、摄像头信号线是否与舵机线长时间并行。

## 如何验证修复

- 固定同一段动作和控制频率。
- 连续运行足够长时间，而不是只看一次动作。
- 同时记录控制周期、丢帧计数、电池电压、5V 和温度。
- 对比修改前后的失败频率和触发条件。
- 在满电、低电量和不同动作强度下重复。

## 常见误区

- 只提高重试次数，不处理电源和地线。
- 只换更粗的电源线，却保留接触不良的连接器。
- 看到单个舵机正常，就认为 HAT 和总线没有问题。
- 把主控因过热降频造成的响应变慢，当成纯通讯丢帧。
